02 · Situation

The situation

Three things this team is usually dealing with when it calls.

Personal accounts, no visibility

Developers sign up for assistants on their own, expense them or pay with their own cards, and paste code into tools nobody reviewed. The organisation cannot say who uses what, on which repositories, or what it costs. Turning that off loses the productivity; leaving it on loses the audit.

Agents that write without a reviewer

An agent that edits files silently is faster until the first bad change ships. Review habits were built around diffs, and tools that bypass the diff bypass the review. Trust has to be earned per change, not granted per tool.

One provider key for the whole organisation

A single shared key means one runaway job empties the budget for everyone, and revoking it means a redeploy. Which model serves which repository is decided by whoever wrote the config last.

05 · In writing

What is in writing

The parts a review asks for, stated once and linked to the page that holds them.

Data terms

Content sent through Runix Router is processed to serve the request and never used for training; operational metadata is kept for billing and support. Put Router in front of the agent and its model calls are covered by the same terms.

Contracting and billing

You contract with Runix AI Inc; an MSA and a DPA are available on request. Router billing is usage-based in USD, itemised, on a prepaid balance or by invoice; Code has team plans, set out on the Code plans page.

Statuses, literally

Runix Code is in development and not generally available; its page describes what is being built, and waitlist cohorts are invited in order. Runix Router is in early access and running traffic, with no published SLA.

07 · Questions

Common questions

Can developers use Runix Code today?

No. It is in development and not generally available; the waitlist is open and cohorts are invited in order. The product page describes what is being built, not a shipped product.

Does the agent commit code on its own?

It is designed so that every change lands as a reviewable diff, never a silent write. Your review process stays where it is.

How do we attribute cost to a team?

Runix Code is designed with seats, per-key limits and usage attribution by developer. Runix Router meters per key, with itemised usage-based billing in USD, so a team's model spend is attached to its key at call time.
